# 性能尖峰分析（2026-09-10）

本轮未复现此前 68.445 ms 的尖峰，不将其报告为已修复。未修改库绘制实现，仅完善性能基准的诊断输出。

## 测量与结果

环境：Windows，Intel Core i5-8400，Release；当前工作区，1280×800，8 个按钮、100,000 行虚拟列表、聚光卡及 Area/Heatmap。每轮预热 30 帧后测量 300 帧，15 个进程顺序运行，性能测试期间未并行运行其他回归程序。未控制用户其他应用、系统调度或功耗状态；显卡型号与实际设备选择本轮未采集。

| 各轮平均范围 | 4.150–4.390 ms |

最差帧在第 14 轮第 296 帧（从 0 编号）：绘制调用 9.665 ms，EndDraw 0.269 ms。各轮 EndDraw 平均约 0.217–0.233 ms；9 个超预算帧中，8 个绘制调用耗时超过 7.8 ms，另一个绘制 6.516 ms、EndDraw 1.712 ms。慢帧分散在不同轮次和帧号，现有样本未显示固定触发位置。

## 结论的边界

- 历史的 7.041 ms 平均 / 68.445 ms 最大值在本轮没有复现。当前数据不支持持续性大幅退化，也不证明历史尖峰已消除。
- 慢帧耗时主要落在 FillRect 与 DrawControlTree 调用区间，而非 EndDraw。该区间包含控件遍历、文本准备及 D2D 调用，也可能包含线程被抢占或驱动等待；不能直接等同于控件纯 CPU 运算耗时。
- 原测试计时止于离屏 EndDraw，没有等待 GPU 完成，也没有窗口 Present、布局、输入或 BeginFrame；所以这是 CPU 墙钟提交耗时，不是完整交互延迟或 GPU 帧时间。没有改变原有计时范围或平均值验收条件。
- 尚无 ETW 调度/调用栈或 GPU 时间戳证据，无法确定历史尖峰根因。后续若再次出现数十毫秒尖峰，应同轮采集线程调度、CPU 调用栈和 GPU 队列，避免依据一次最大值修改控件或渲染架构。

本轮构建成功，visual 与 anim 最终 ALL PASS，api 退出码为 0。visual 在 UIA 单元格检查后曾长时间没有新输出，随后自行完成；最终核实进程已退出，无须终止。此停顿不作为性能基准尖峰的归因证据。相关日志为 `build/perf-analysis-{visual,anim,api}.log`。
