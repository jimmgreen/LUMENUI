# 第二轮性能优化：折线顶点批量提交

日期：2026-09-19。本轮基于上一轮三角形复用后的工作区继续，保留全部既有改动；不是以 HEAD `c917b4a` 的原始实现作对照。上一轮记录见 `docs/mcp-performance-triangle.md`。未提交、推送或发布。

## 实现范围

- `src/core/painter.cpp` 的 `Painter::StrokeOpenPolyline` 原先逐点调用 `ID2D1GeometrySink::AddLine`。
- 两点短线仍直接调用一次 `AddLine`；其他长度以固定 256 点批次调用 `AddLines`。249 点折线的顶点提交从 248 次减为 1 次，2049 点从 2048 次减为 8 次。
- 全程仍只创建一个 figure，一次 `BeginFigure`/`EndFigure`，批次之间不结束路径，因此不改变连接、端帽、虚线相位或线宽。
- 使用 2 KB 固定栈缓冲显式转换 Point，避免跨类型指针重解释与严格别名风险。批次按剩余点数推进，不截断长折线，不引入增长型缓存或 C++ 堆分配。
- 路径对象本身仍会重建，不能称本轮实现了折线几何缓存或消除了所有 D2D/驱动分配。公共 API、资源生命周期、图表数据及主题未改动。

新增回归位于 `tests/perf/main.cpp` 和 `tests/visual/main.cpp`；上一轮公共头及三角形实现保持不变。

## 实施中发现的回退

首版全长度批处理的 5 对 A/B 显示：2049 点 Draw 均值下降约 14.7%，典型场景仅下降 0.16%；两点短线 Draw 均值从 0.003854 ms 增至 0.004022 ms，回退约 4.4%。据此为两点路径保留原始直接提交方式，然后重新构建、回归并完成最终 5 对 A/B。

首版日志与最终日志分别保存，不混合样本。短线测量绝对量级很小，应结合波动理解，不能只用一个百分比推断整机体验。

## 最终 A/B 条件

- 同机 MSVC Ninja Release / bundled shared LumaText，沿用上一轮已核对源码根的隔离构建目录；不是直接运行未核对的仓库旧二进制。
- 新性能测试先加入，再以本轮优化前库实现构建 `round2-baseline.exe`；最终实现构建并保留 `round2-optimized.exe`，性能测试代码完全相同。
- 其他构建、自动回归及 Gallery 导出结束后，串行运行 5 对；奇数轮 baseline→optimized，偶数轮反向。
- 典型场景仍是 1280×800、8 按钮、100,000 行虚拟列表、聚光卡、Area/Heatmap，每次 300 帧，每版本共 1,500 帧。
- 折线基准覆盖 2/249/2049 点，每帧 16 条，实线与虚线交替，顶点每帧变化；每档预热 10 帧、采样 120 帧，每版本每档共 600 帧。生成基础点列不计入 Draw；绘制前后分别计时，另外记录包括 EndDraw 的提交耗时。
- 下表均为 5 次等样本均值的平均，单位 ms；变化为优化后相对基线的耗时变化，负值表示下降。

场景最差帧为 baseline 3.579 ms、optimized 3.265 ms；≥8 ms 帧分别为 0/1,500 与 0/1,500。不同轮次存在波动，本轮只确认中长折线构建/绘制路径的局部 CPU 开销下降，不把典型界面的小幅均值变化称为明确整体提速。

最终两点短线 Draw 均值仍增加约 7.08%，绝对值约 0.000268 ms/16 条；其包含 EndDraw 的提交均值也增加约 2.87%。保留直接 AddLine 路径不等于已证明回退消除。249 点 Draw 降幅约 20.96%，但包含 EndDraw 的提交均值增加约 0.22%；2049 点 Draw 下降约 15.87%，提交仅下降约 0.87%。本轮是有明确输入规模边界的局部优化，不能宣称所有输入或整体界面都更快。
